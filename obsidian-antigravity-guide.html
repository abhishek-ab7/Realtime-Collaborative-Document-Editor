01

Why Obsidian + Antigravity is Perfect

Most developers use Obsidian to store notes in a vault. But they don't connect it to their AI coding agents. You're about to build something better: a live knowledge base that powers your entire build.

Obsidian's Role
  • Single source of truth — all context about your project in one place
  • Git-synced — every note lives in your repo. History preserved.
  • Linked graph — "Yjs sync issues" note automatically links to all related decisions, code snippets, reference repos
  • Offline-first — works when internet drops. Sync on reconnect.
  • Local-first — AI agents read directly from your filesystem, no API latency
Antigravity's Role
  • Reads your vault — via file system or GitHub repo context
  • Executes tasks — while your Obsidian vault stays open in the background
  • References notes — when agents need context, they pull from your linked notes
  • Updates progress — agents can write new notes to your vault (with your permission)
  • Parallel execution — multiple subagents reference the same notes simultaneously

03

Step-by-Step: Install & Configure Obsidian

1

Download Obsidian

Go to obsidian.md. Download for Mac/Windows/Linux. Install it.

2

Open Your Vault

Launch Obsidian. Click "Open Folder as Vault". Navigate to your repo and select the docs/ folder. Done — Obsidian now watches all .md files in there.

3

Enable Core Plugins (no third-party needed)

Obsidian → Settings → Core Plugins. Turn on:

  • Graph View — see the linked knowledge graph of your decisions
  • Backlinks — see what notes link to the current note
  • Outline — table of contents for the current file
  • Sync — if you want cloud backup (Obsidian Sync = $8/mo, optional)
4

Configure Preferences

Settings → Files & Links:

  • New note location: docs/03-daily-logs/current-phase/ (will be your log folder)
  • Use [[wikilinks]] (already default)
  • Automatically update internal links: ON
5

Create the first file

In Obsidian, click "New Note" and paste the 00-index.md content from section 2.2. Save it. You now have a working vault.

6

Commit to Git

cd collab-editor
git add docs/
git commit -m "feat: initialize obsidian vault structure"
git push

Your Obsidian vault is now version-controlled.

## Obsidian Vault Integration
The project knowledge base lives in docs/ as an Obsidian vault.
All decisions, architecture notes, debugging logs, and phase progress are here.

### Key Files Agents Should Read First
- docs/00-index.md — Navigation hub
- docs/01-project-overview/tech-stack.md — Current stack
- docs/01-project-overview/constraints.md — Hard rules
- docs/04-architecture/yjs-sync-design.md — Core architecture
- docs/04-architecture/api-routes.md — API contract

### When Creating New Notes
1. Always use markdown (.md extension)
2. Place task-specific notes in the correct folder:
   - Phase work → docs/03-daily-logs/phase-X-logs/
   - Architecture decisions → docs/04-architecture/
   - Bugs/fixes → docs/06-debugging/
3. Use wikilinks for internal references: [[path/to/file|display text]]
4. Create a summary at the end of each phase in docs/02-phases/phase-X.md

### Linking Strategy
- Obsidian auto-creates backlinks. Don't worry about two-way links manually.
- When writing docs, reference related files: e.g., "See [[04-architecture/socket-io-flow]]"
- Use [[404]] syntax (broken links shown in red) to mark TODOs

Primary:   gemini-3.5-flash (fast, coding tasks)

UI:        gemini-3.5-flash (React components, design)

- Subagents can write to docs/ simultaneously (different files only)
- Each subagent should log its progress: docs/03-daily-logs/phase-X-logs/subagent-A-log.md
- Final summary merged into phase-specific notes at the end

## No-Go Zones

- CLAUDE.md (Claude Code's config)
- Any files in /apps/web, /apps/server (those are code)
- .gitignore in project root

OK to modify:
- All files in docs/
- PRD.md (if updating requirements)
- docs/.gitignore (Obsidian local settings)
05

How Antigravity Reads Your Obsidian Vault

You don't need special integrations. Antigravity works with files directly. Here's the exact workflow:

The Active Workflow (How You Use It)
1. Open Obsidian on your laptop. You keep it open while building. It's your side-by-side reference.
2. Open Antigravity (or use Claude Code CLI). Point it at your repo: antigravity open /path/to/collab-editor
3. Reference When you run a task in Antigravity, include in your prompt: "Read docs/04-architecture/yjs-sync-design.md before implementing." Antigravity fetches it from disk.
4. Write Agents write progress notes to docs/03-daily-logs/. You see them appear in Obsidian in real-time (Obsidian auto-refreshes).
5. Review Click back to Obsidian. Read what agents wrote. Add your own notes. Create backlinks. The graph grows.
6. Commit At the end of the day: git add docs/ && git commit -m "docs: add phase X progress"
✓ Key: Antigravity ≠ Connected to Obsidian

Antigravity doesn't have a special "Obsidian integration." Instead, you give Antigravity the file paths. The workflow is:

  • You tell Antigravity: "Read the file at docs/04-architecture/yjs-sync-design.md"
  • Antigravity reads it from your filesystem (because you pointed the agent at your repo)
  • Agents reference the content in their reasoning
  • Agents write new files back to docs/03-daily-logs/
  • Obsidian detects the new files and displays them (because Obsidian watches the docs/ folder)

08

Advanced: Auto-Sync with GitHub & MCP (Optional)

Once you have the basics working, you can add automation so Antigravity agents automatically commit changes back to GitHub. This is optional but cool.

What This Does

Agent finishes work → automatically commits to a feature branch → pushes to GitHub. You wake up to a ready-to-review PR.

8.1

Enable GitHub MCP in Antigravity

Antigravity 2.0 has built-in GitHub integration via MCP (Model Context Protocol).

Setup:

  1. Go to Antigravity Settings → Integrations
  2. Click "Connect GitHub"
  3. Authorize the app (it asks for repo read/write permissions)
  4. Choose your collab-editor repo
  5. Done. Agents can now commit directly to GitHub.
8.2

Tell Agents to Commit & Push

Add this to your Antigravity prompts:

# At the end of your Antigravity prompt, add:

COMMIT & PUSH:
When your work is complete:
1. Create a new branch: phase-2-impl-[date]
2. Commit all changes to docs/ and code with a conventional message:
   git commit -m "feat(phase-2): implement socket.io sync handlers"
3. Push the branch: git push -u origin phase-2-impl-[date]
4. Create a pull request with a summary in the PR description

PR Template:
Title: Phase 2: Socket.io + Yjs Sync Implementation
Body:
- [ ] Sync-step1/step2 protocol implemented
- [ ] Server-side Y.Doc management working
- [ ] Client sync verified in test (2 browsers)
- [ ] No TypeScript errors (strict mode)

Close with: "See docs/02-phases/phase-2.md for full details."
⚠ Important: GitHub Token Security

Antigravity handles your GitHub token securely. It's stored in your local Antigravity config (not in git). Never commit tokens. If you're paranoid, use a GitHub fine-grained PAT (Personal Access Token) with limited scope.

09

Troubleshooting: What Can Go Wrong

Problem Solution
Obsidian shows old files, not the new ones Antigravity wrote Obsidian caches metadata. Click the refresh button (or close/reopen). Usually fixes within 10 seconds. If not: Obsidian → Settings → Files & Links → toggle "Automatically update internal links" off then back on.
Antigravity can't read docs/ files Make sure you pointed Antigravity at the repo root: antigravity open /path/to/collab-editor (NOT /path/to/collab-editor/docs). Antigravity reads the whole tree.
Agents are writing files to the wrong folder Your GEMINI.md is unclear about folder structure. Add explicit paths to the prompt: "Write the output file to: docs/03-daily-logs/phase-X-logs/file-name.md (full path)"
Wikilinks are broken (red text in Obsidian) The file path is wrong or the file doesn't exist. Hover over the red link → click the suggestion → or create the missing file. Obsidian will fix the link automatically.
Git merge conflicts in docs/ after agent pushes Agent writes to docs/03-daily-logs/phase-X-logs/subagent-A.md and you manually edit docs/03-daily-logs/phase-X-logs/day-5.md — Git conflicts. Solution: agents should only touch their own files. You manually edit daily logs. Document this in GEMINI.md.
Antigravity "forgets" context between sessions Antigravity in 2026 has auto-compaction, but you can manually help: at the start of a new session, add to your prompt: "First, read docs/02-phases/phase-X.md to get context on what we're building."
